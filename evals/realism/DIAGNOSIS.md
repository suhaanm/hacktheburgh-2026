# Why our synthetic data only shows planted structure (diagnosis, v1)

REALISM track, Sat 7 Nov 2026. Everything below is read from the v1 code (`services/engine/understudy_engine/personas/`) and from small measurements of the files in `data/synthetic/` (`evals/realism/measure_v1.py`, read-only; run it with `uv run --package understudy-engine python evals/realism/measure_v1.py` on the seeded v1 data). Nothing here claims real data looks a particular way beyond what the cited sources say, and every source is marked with how well it was checked (see "Citation status" at the end).

## The short answer

The pipeline recovers planted structure for six reasons, in order of how much I think each one matters:

1. **The label is made by the same code as the behaviour.** The hazard label ("no `progress` event in the next 60 s") is read from `progress` events that the generator writes at the end of every productive cog, deterministically (`personas/generate.py:256-258`, `apprentices.py:200`, 0.05 s before the cog ends; soft cogs 40 percent of the time). Stuck spells are built from a fixed vocabulary of detour cogs with no progress inside them (`tasks.py:134-153`), which are exactly the features the model reads (n-grams of SEARCH, REFORMULATE, repeats; `hazard/features.py`). Measured: 25 percent of the label-1 bins fall inside a planted spell; the rest are stretches of non-productive cogs, which the model finds because the cog grammar says which cogs ever emit progress. The model is partly learning the generator's emission table.
2. **There are four people.** Four personas (`profiles.py`), three learners, 24 apprentices with two scripted cases each (`apprentices.py:32-34`). Every person-level number has a handful of clusters behind it, so "between-person variation" is whatever four seeds happened to give.
3. **Deficits are five discrete injections, constant per person.** Each novice gets each of five deficits with a coin flip (`apprentices.py:217-224`, p = 0.5) and the set is identical in both of their cases: measured 16 of 16 novices have the same deficit set in both cases, 0 of 16 have no deficit, the number of deficits is 1 to 5. Each deficit is a fixed block with an exact price (`apprentices.py:180`: a pause is U(30, 75) s). The method is then asked to find five known blocks.
4. **Experts are one script.** All eight experts follow one 15-step sequence; two use the one allowed reordering (`apprentices.py:264`). Measured: 2 distinct expert cog sequences in 16 expert traces. Novices differ from experts by construction in speed: expert speed U(0.92, 1.08), novice U(1.12, 1.40) (`apprentices.py:267, 272`), so the speed ranges do not overlap (measured: the slowest expert total is 405 s, the fastest novice 438 s). The placebo (expert against expert) therefore attributes 0.0 s to every deficit (`evals/report.md`) and the detection threshold sits at its 1 s floor.
5. **Timing is clean, narrow and stationary.** Lognormal dwell with one sigma per group (0.15 experts, 0.25 novices; routines 0.18 to 0.33; ad hoc 0.4; `apprentices.py:269-274`, `profiles.py`, `tasks.py:102-105`), clipped to [2.5, 160] s. Measured expert dwell: log-SD 0.12 to 0.22 and p99-over-median 1.3 to 1.7. Events inside a cog sit on a near-regular grid with spacing U(6, 12) s (`vocab.py:121-135`); measured inter-event p99-over-median is 3.2. There is no learning inside the 2-case apprentice study, one shared skill curve in the personas (same alpha 0.7 and n0 120 for all four, only s0 differs, 0.22 to 0.30; `tasks.py:16-17`), no fatigue, no time-of-day effect, no warm-up, no forgetting except in `learners.py`.
6. **No capture noise and no interruptions.** The emitter never drops, duplicates or mis-zones an event (measured: 0 duplicate events in 4309; every event carries a task id; task markers are exact), a task boundary is given for free (`task_start` and `task_end` on every task), and nothing interrupts a task: background noise events are untagged (`generate.py:108-115`, `task=False`) so they never enter an episode. Stuck self-reports are a fixed 35 percent (personas, `tasks.py:153`) or 60 percent (apprentices, `apprentices.py:207`) of blocks.

The pipeline is not wrong; the test is too easy. The evaluation shows it is consistent with a generator we wrote.

## What v2 will not fix

* **Still synthetic.** Every v2 dataset keeps the badge "synthetic, realism-calibrated". The ranges make the data plausible; nothing makes it real. A pipeline that does well on v2 has shown robustness to *these* structural changes, written by the same team in the same repository.
* **The label circularity** (row 13) remains: progress and stuck are defined by events we generate.
* **Shared parts across the three v2 families:** the person hierarchy, the interruption post-process, the event emitter with its noise model, the role's cog vocabulary and the task grammar's valid paths. They differ in how sequences, durations and deficits are generated. A family with less shared code would be a stronger test; the shared parts are listed in the report.
* **Constants I could not verify** (see below) use deliberately wide ranges, so "within published ranges" is a weak statement for those.
