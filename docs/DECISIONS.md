## REQ-10 computer-use study (7 Nov)

Analyst REF-CU, read-only; full note in `docs/reference-notes/computer-use-comparison.md` (Clicky parts MIT; Sentient OS parts are a clean-room summary, ideas only, AGPL-3.0 design-only under D24). Nothing from `references/` or the owner's reference copies was run.

**Verdict.** Their approach does not show that it avoids our problems; the tasks are not comparable. Clicky's app never acts (it points); its Windows fork's plugin executes single actions by coordinates for an outside agent, with no loop and no task in the repo. Sentient OS runs a real multi-step loop on real apps, but the loop and context handling live in the Codex CLI and a vendor-signed helper (not in the repo), its success signal is the model's own final claim, and the repo holds no completion measurement. The owner's belief that they do not face our reliability problems is untested, not confirmed. Sentient's design (element-level actions and value writes, read before write, never replay an action) plausibly avoids some native drop-down trouble, but that is a design inference.

**Findings from our own code and results (not from the references).**
- The held-out "false stop" (hh_0001, nav-c step 25) has stop code `off_goal_unavailable`, which in `security/drift.py` means the goal-check model call failed to run and the layer paused by design; the gate itself said fill. It is not a mis-classification of a native select, so the working description in `ITERATIONS.md` should be read that way. Every click and key press makes one such call and there is no retry. The stored file keeps no error class.
- The wrong figures on B were caught by the sandbox oracle in `live_t3.py`. The product's `check_completion` compares the case note with what navigators read and would not catch a wrong, well-formed figure. No per-step typed-input trace exists, so B's cause is undiagnosed; dev households of the same archetypes passed with the same drop-down values.

**Top three adaptations (details, effort, licence status in the note).**
1. **Typed-input read-back and pre-submit audit** (5 to 6 h; `tiers/form_audit.py` new, wired into `tiers/computer_use.py`, `navigator._tier3`, `completion.py`): code reads every form control from the DOM, compares with the facts it typed, blocks the submit click on a mismatch, keeps a per-step record of handle, field role and match yes or no (never values). Fixes (a) at the input side and supplies the missing trace.
2. **Retry the goal check, never the action, and record the error class** (1 to 2 h; `security/drift.py`, `security/pipeline.py`): a bounded retry before failing closed. Addresses (b) as it occurred.
3. **Set a native drop-down by fact through code** (6 to 8 h; `tiers/computer_use.py`, `tiers/facts.py`, `security/gates.py`, provider tool schemas): no clicks at pop-up options, no Enter. Plausible for (c) and part of (a); first confirm the pop-up premise with a 30-minute offline test with no model, and check that the OpenAI computer-tool path accepts a second function tool.
