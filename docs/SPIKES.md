### S2 follow-up: supervised check of the agent's `MacActuator` (7 Nov 2026, about 15:30 GMT): FAILED, bug found, real runs frozen

Owner present and said go. A dry run through the safety pipeline looked right. The real run (`mac_check --real --target TextEdit --click-px 1200 800 --text hello`) reported `ok: true` but TextEdit's document was empty. Cause, verified afterwards with `CGWindowListCopyWindowInfo`: (1) the real backend reported display scale 1.0 (on this Retina Mac `CGDisplayPixelsWide` returns points; `NSScreen.backingScaleFactor` is 2.0), so pixel (1200, 800) was clicked as point (1200, 800) instead of (600, 400); (2) the topmost window at that point was **the Claude desktop app's own window**, not TextEdit, so one real click and probably five typed characters went into the owner's chat window (no Enter was sent); (3) the guards passed because the frontmost-app check ran before the click and the typing step saw a stale frontmost value. Fixes required before any further real run (sent to agent-core): scale from `NSScreen`, cross-checked; a hit-test guard (the topmost layer-0 window at the click point must belong to the target app); wait-and-verify focus after every click and before every typed chunk; tests with a fake backend for each failure. **Lesson for the lead:** hit-test the target point against the window list before running any real-input check, not after. The first spike (S2, `scripts/s2_textedit_test.py`) passed because it positioned TextEdit itself and aimed inside its window. Real desktop runs stay frozen until the owner re-approves a retest.

## S3: browser capture

- [ ] Launch a headed persistent Playwright context with the extension loaded.
- [ ] Capture one event and see it in the engine.
- **Decides:** the capture architecture and the test approach for the extension.
- **Result (7 Nov 2026, platform agent): PASS.** Playwright 1.65 with bundled Chromium 158: `launchPersistentContext(userDataDir, {headless:false, args:['--disable-extensions-except=<dist>','--load-extension=<dist>']})` loads the unpacked MV3 extension; the service worker is reachable through `context.serviceWorkers()` and can be driven with `sw.evaluate(chrome.storage...)`. Ten events from a real page (nav, click, focus, scroll, search) reached a local stub server in about 3.3 s from launch (2 s of that is the batch timer); all schema-valid (Ajv against `event.schema.json`), with no page text, URL or secret in the payload. Real clicks, typing and Ctrl+V in a login form (password field) produced zero events. The click `label_hash` matched an independent Node recomputation of the salted hash. The rect request from a stub desktop app was answered with a schema-valid rect equal to `getBoundingClientRect`. Also passes in new headless mode with `channel:'chromium'`, so CI can run it without a window; extensions do NOT load in the old headless shell. **Decides:** capture architecture = content script (isolated world, local salt) + service worker (batching, consent poll, rect poll); test approach = vitest/jsdom for logic (155 tests) plus `npm run spike:s3` for the real-browser path against stub servers on ephemeral ports, never the real engine. Gotchas: a first-run race (fixed), `isTrusted` events only (synthetic `dispatchEvent` is ignored by design), the rect `window_offset` is an approximation (`screenX/Y + (outerH - innerH)`) that is **not yet verified against pixels** and must be calibrated in the desktop COA-2 test, and cross-origin iframe rects are frame-relative (the answer carries `frame_id`).
