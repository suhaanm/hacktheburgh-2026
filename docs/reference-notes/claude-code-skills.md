# Reference note: how Claude Code loads skills and runs headless (Track T)

Not a repository in `references/`: the owner's own installed Claude Code (2.1.319) and its `--help`, read on 8 Nov 2026. Nothing was copied; this is what Knack's task code takes from the idea, in our own words.

**Skills.** A skill is a folder with a `SKILL.md` that starts with YAML front matter (`name`, `description`) followed by instructions. The tool indexes only the front matter up front and reads the body when a skill is chosen (progressive disclosure), so a large library costs little context. Knack does the same in `tasks/skills.py`: a bounded local scan, front matter only for the index, BM25 over name and description to choose, and the body (size-capped, wrapped as untrusted guidance) only for the top two. For the Claude agent route Knack does not load skill text at all: the CLI loads `~/.claude` skills itself, and Knack adds the chosen names to the prompt as a hint.

**Headless runs.** `claude -p "<prompt>" --output-format stream-json --verbose` prints one JSON event per line: `system/init`, `assistant` (with `tool_use` blocks), `user` (tool results), `result` (final text, `is_error`, `subtype`, turn count and `total_cost_usd`), plus hook and rate-limit events. `--permission-prompts none` refuses anything that would prompt, `--permission-mode acceptEdits` plus `--allowedTools` fixes what may run, `--session-id` names the session, `--settings` takes deny rules as JSON. Knack's monitor turns `tool_use` into "tool name plus a file's base name", reads `result` once, and ignores every other event; none of an event's contents is shown or stored.
