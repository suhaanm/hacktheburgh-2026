# HRT brief: predictions and decisions

*Hack the Burgh XIII, Knack (built as Understudy). Written for the Hudson River Trading judges, "best use of data for predictions and decisions". We could not find the official brief, so this is written to the lens a quantitative judge uses: probabilistic forecasts scored with proper scoring rules, honest out-of-sample tests with baselines and intervals, no leakage and no forking paths, decisions judged by realised cost against naive and oracle policies, and a plain account of when the model fails.*

**Every number in this document is generated.** `scripts/hrt_brief.py` reads it from `evals/report.json` and the other files under `evals/` (a test fails if the committed text differs from a fresh render, and if a sentence that says "beats" or "loses" stops being true). **All data is synthetic or simulated**, from generators we wrote, and each result says so. The live study (n = 4 teammates) has not run. Nothing here is a claim about real workers.

## 1b. The data pipeline, in one paragraph

**Input** is the always-on level-0 event stream only (event kinds and times, hashed): no page text, no URLs, no field values, and never a field listed in `packages/schema/sensitive_fields.json`. **Cleaning and features**: events are cut into episodes (one task attempt by one person) and every 30 seconds a bin is made whose label is "no progress event in the next 60 seconds"; a bin's features use only what had happened by then (the last three event kinds as hashed n-grams, seconds in the current event, repeats, reformulations since the last progress, seconds since progress, and a role prior computed from training people only), and bins whose look-ahead would run past the end of the episode are dropped because their label is not observed (a test truncates the future and rebuilds every feature). **Models**: an L2-regularised logistic regression for the stuck forecast, a discrete-time survival head for the time to the next progress event, a logistic router for the risk that an agent's answer is wrong, a ridge regression of log seconds remaining for the finish range; each is fitted once on a training pool and frozen. **Held-out evaluation**: leave one person out first, then a prospective replay in which every forecast and every naive baseline's forecast is written to a hash-chained ledger before its outcome exists, scored only from that record on seeds nobody used, with a conformal quantile calibrated once at deployment. **The decision is made by code**, not by the model: a break-even threshold for "interrupt", a registered rule for "which cases a person reviews", and an e-process guard that decides when to fall back to the naive predictor; the model only proposes the number. **Where the data never goes**: the ledger stores a salted-hash stream key, a forecast and a label, never text; logs and memory stay on the device; screen frames are not part of this pipeline (a frame is held in memory for one call and never written to disk). **Every number in this brief comes from generated events with the same shape as the real stream**; none of this has run on real workers.

## 3. What a quant judge will attack, and our answer

**Leakage.** *Attack:* a model predicting "no progress in the next minute" from event streams can leak the label through its features or through the split.
*Answer:* the features are causal (a test truncates the episode at each bin and rebuilds them; identical). The split in the prospective part is in time: the models are fitted once on a training pool, frozen, and every forecast is appended to the ledger before its outcome exists; the ledger refuses a prediction older than the newest entry and an outcome earlier than the horizon; the online baseline reads only outcomes the ledger has already resolved (a test recomputes it from the record). The held-out seeds are disjoint from every earlier evaluation (a test). *What we do not claim:* the v1 world draws new people of the four persona types the model was fitted on; the label is defined from the same `progress` events that the generator emits.

**Generator dependence.** *Attack:* a model fitted and tested on our own generator measures the generator.
*Answer:* we tested that, on purpose, and report it. {{rt:findings/id=realism-generator-dependence/text}} The prospective part repeats it on new seeds.
