# Context audit of the Knack model-facing and voice-facing surfaces (detail behind docs/KNACK_DEMO.md section 6)

Method. A read-only pass over the code (nothing was run), done by a sub-agent of DEMO-DIRECTOR against main at e2a9ad8 and the unmerged branches then open, then re-checked by the director against main after the merge of WAKE-VOICE's final commits (the Live context packet). The audit asks, for each surface: what context it is fed, which module builds it, how it is bounded, and what is missing. The rules it measures against are in `docs/CONTEXT_ENGINEERING.md` section 2 (typed first, trust by audience, stable first, bounded, fresh or named, measured). Anything not read in code or not run is marked unverified. Paths are relative to the repository root.

## 2. The gaps, ranked (R = real code gap, D = documentation gap)

1. **G1 (R). The Live packet misses the top Home insight.** `reportInsight(id, template)` in `apps/dashboard/src/lib/wakeContext.ts` is not called by any screen (only `trackRoutineRun` is, from Routines), so `home_insight` is always listed as `unknown`. One call where Home settles on its hero closes it (the id is the pointer's `id`; the template is the id of the template the sentence was built from).
2. **G2 (R, small). The routine in the packet is reported only for a run started with Run now from Routines.** A run started any other way stays unknown. The packet also carries no "needs you" item kinds (blocking or not), only the count.
3. **G3 (R, a decision). The window does not minimise for a sandbox run** (see surface 2). The pill does show. The owner's wish needs `realScreen` to be true for a run the worker started from the Knack window, or Command-M in the take.
4. **G4 (R). Hero budgets are unenforced at runtime for 8 of 11 pointer kinds.** Not hit by the seeded data.
5. **G5 (R, by design in part). The packet carries no help level and no "working" run state:** the voice session ends when an agent starts acting (`startRefusal` agent_acting), so the voice cannot answer "how is the run going".
6. **G6 (R). The approval card carries no id or count.**
7. **G7 (R). The engine's grounding input is dead outside fixtures.**
8. **G8 (D, honesty). The memory file is in no prompt.** Say "rules".
9. **G9 (R, low). A point label is model text.**
10. **G10 (D). Doc lags:** `docs/CONTEXT_ENGINEERING.md` says the reader memo is open and no caller passes a manifest, both now built (tier 2, tier 3 and the orchestrator pass manifests); row 13 omits the wake instruction and tools; the freshness tables have no rows for queue count, run state, help level, screen or insight; the Live prompt header still names the persona Understudy and the insight templates still say "Understudy" in strings.
11. **G11 (R, not a context gap but a link the audit found): approving an agent item does not submit it.** `POST /run/{run_id}/finalize` presses the real submit button for an approved item and works (verified on a private stack), but no code in `apps/dashboard` or `apps/desktop` calls it.
12. **Not built:** the Ask bar (typed text) has no specified model path; the legacy chat path is free text behind `UNDERSTUDY_LEGACY_REMOTE` (off). It must use the same packet and enums when built.

## 3. The Live packet: what the audit proposed, what exists, what is left

The first audit (at e2a9ad8) found the Live session started from a static instruction and proposed a packet of enums, ids and counts. WAKE-VOICE built it (`wake/context-packet.ts`, `wake/context-source.ts`, `docs/knack-ux/09-wake-voice.md`, "The context packet") and it is bound on main (`index.ts`: `createContextHub`, `context: contextHub.build` passed to `registerLive`).

| Field the audit proposed | Now in the packet? | Source | Freshness limit |
|---|---|---|---|
| screen id | yes (`screen=`), only while the Knack window is focused | `knack.mainWindow` URL, `screenIdFromUrl` | 60 s |
| top insight id | **no reading arrives** (G1) | `reportInsight` is never called | 1 h |
| needs-you count | yes (`approvals_pending=`) | HUD model `queuePending` (30 s poll) | 60 s |
| run state and routine step | partly: `routine=<id> step=n/m` only for a Routines "Run now" run (G2); no `working` state (G5) | `trackRoutineRun` | 30 s |
| help level | no (G5) | `coach-chip` has it | n/a |
| coach step and zone | yes (`coach=step=... zone=...`) | `coachBox.last` | 60 s |
| task in progress, step n of m | yes (`task=`) | `coachPoller.lastState().task` | 60 s |
| Cue state | yes | `cue.controller.visible()` | 20 s |
| consent words, frames allowed | yes | Live and wake settings | read at open |
| whether a click can ever happen | yes (`click=`) | the rung record | read at open |
| data mode (live or example) | yes (`data=`) | `UNDERSTUDY_MOCK` | read at open |

Unverified: whether a resumed Live session accepts a changed setup; whether a text turn mid-session can trigger a spoken reply; whether sliding-window compression keeps the system instruction (it should; test live). The packet goes in the setup, not in a text turn, for that reason.
